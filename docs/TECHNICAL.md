# 기술 문서

## ROM 구조
- 원본은 복호화된 NCSD(`.3ds`)이지만 NCCH의 NoCrypto 플래그(0x18F 비트 2)가 꺼져 있습니다. 빌드 시 켭니다.
- `tools/ctr.py`: NCSD → NCCH → ExeFS / RomFS 추출. `tools/build.py`: RomFS 파일 교체 후 IVFC 해시 트리·NCCH 헤더·NCSD 파티션 표 재작성, 새 `.code`는 비압축으로 넣고 ExHeader 압축 플래그를 끕니다.
- `.code`는 표준 BLZ 압축(`tools/codeblz.py`).

## LINKDATA_A.BIN
- 거의 모든 데이터가 `Data/LINKDATA_A.BIN` 하나에 있습니다(엔트리 19,165개).
- 헤더 0x10 바이트 뒤 엔트리 표 `[u32 오프셋/0x20, u32 0, u32 저장 크기, u32 원본 크기]`. 원본 크기가 0이면 비압축.
- 압축 엔트리: `u32 원본 크기` + `[u32 길이 + zlib(레벨 9)]` 청크(32KB 단위) 반복 + **길이 0 종료 청크(u32 0)**. 종료 청크가 없으면 일부 엔트리(폰트 등)를 읽을 때 게임이 PANIC으로 멈춥니다.
- `tools/link.py`: 해제·재압축. 변경 없는 엔트리는 원본 그대로 재배치합니다.

## 텍스트
- 문자열 표: `u32 개수` + `[u32 오프셋, u32 길이]` × 개수 + NUL 종료 UTF-8 문자열. 표가 중첩되기도 합니다(`tools/tree.py`가 재귀적으로 해석·재구성, 무변경 시 바이트 단위 동일).
- 후리가나는 `【漢字：かな】` 형식(번역 시 제거). 제어 태그 `【r】【g】【b】【y】【G】【e】`(색), `【Str1】【Unit1.strName】【交換相手】` 등(변수), `【縮小】【幅小】`는 보존.
- 무장 요괴 이름(표 00057/0)과 가타카나 읽기(00057/1), 아이템 이름(00057/25)과 읽기(00057/26)는 같은 번호끼리 대응하며 읽기 쪽은 이름 번역을 그대로 씁니다.
- 컷신 음성 자막(매직 `62 29 00 00`): `u32 개수` + 오프셋 표 + `[float 시작, float 끝, 문자열]`(`tools/subs62.py`).
- 창은 문장별 원문 줄 수까지만 표시합니다(넘치면 마지막 줄이 앞 줄에 붙음). 번역은 줄 수·줄 폭을 원문 이하로 맞췄습니다(`tools/check.py`).

## 폰트
- 시스템 공유 폰트를 쓰지 않고 게임 자체 폰트를 씁니다.
  - 글리프: LINKDATA 0번 GT1G, A4(4bpp) 텍스처 6장(상하 반전 저장). 0~2번이 16·14·12px 본문, 3번 반각, 4·5번 8px 후리가나.
  - 코드표: `.code` rodata 0x615350, UTF-8 바이트를 묶은 정수(예: `【`=0xE38090)의 정렬 배열(이진 탐색). 폰트 기술자 0x61BF74(0x18바이트 × 6: 코드표 포인터, 텍스처 크기, 셀 크기, 열·행, 글자 수/칸 수).
  - 세 본문 폰트의 코드표 3개(연속 배치)를 하나로 합쳐 쓰고, 14px 시트 칸 수(2,628) 안에서 기호 139 + 가나 171 + 한글으로 구성했습니다(`tools/ykfont.py`). 전각 문자는 고정폭.
- 가나 칸에는 한글 음절 글리프를 넣었습니다(`tools/kanamap.py`). 본문에는 가나가 남지 않으므로, 가나 코드를 순서대로 찍는 이름 입력 키보드에 한글이 표시되고 입력한 이름도 한글로 보입니다.
- 공백: 폭 측정 함수가 ASCII 공백을 반 칸으로 세지만 그리기는 한 칸이라 가운데 정렬이 어긋났습니다. 측정 함수 0x52D20C의 공백 분기를 NOP 처리해 둘을 일치시켰습니다.
- 키보드 버튼 이름 등 `.code` 안 일본어 라벨은 바이트 길이 안에서 제자리 교체.

## 그림 글자(텍스처)
- GT1G: 헤더 뒤 텍스처별 8바이트 헤더(포맷, 크기 log2). 헤더 7번째 바이트에 0x10이 있으면 확장 헤더(+u32 길이)가 붙습니다. 포맷 0x3D=RGBA4, 0x3B=RGB565, 0x09=RGBA8, 0x44=A4, 0x47=ETC1, 0x48=ETC1A4.
- SARC 안 BFLIM: swizzle 값 4는 90° 회전 저장(가로세로 뒤바뀜), 8은 일반 저장.
- `tools/texdec.py`(디코더), `tools/imgenc.py`·`tools/etc1enc.py`(인코더; ETC는 바뀐 4×4 블록만 재인코딩), `tools/texpatch.py`(교체), `tools/texindex.py`(원본이 같은 사본 전체에 교체 전파).
- 대상 찾기: 모든 텍스처를 PNG로 풀어(`tools/dumpall.py`) Windows OCR(일본어)로 검출(`tools/ocr`).
- 필살기 배너는 LINKDATA 00203+i = 기술 i번, 무장 요괴 이름판은 12205+i = 유닛 i번이라 번역문으로 자동 생성(`tools/banner.py`, `tools/plate.py`). 나머지는 이미지별 편집 명세(영역·배경 처리·글자·색)를 `tools/apply_edits.py`로 적용, 타이틀 로고는 `tools/logo.py`.

## 검증 도구
- `tools/launch.py`, `tools/shot.py`, `tools/ctrlkey.py`, `tools/emu.py`: 포터블 Azahar를 비활성 창으로 띄우고 창 메시지로 키 입력·스크린샷(Ctrl+P)을 보내 사용자 조작을 방해하지 않고 확인합니다. `tools/gdb.py`: Azahar GDB 스텁 클라이언트. `tools/arm.py`: capstone 디스어셈블 보조.
